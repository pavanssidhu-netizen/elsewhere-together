You are the lead game engineer and product designer for a five-hour web-only ElevenLabs-sponsored game jam. Your task is to BUILD and TEST the complete game "Elsewhere, Together" based on the attached `elsewhere_together_implementation_spec.md`. Read the entire specification first, then implement it, not just discuss or mock it up.

The single most important experience: a tiny amber pixel-art character navigates uncertain events in a rainy coastal town, observed through a moody retro pseudo-operating-system interface. An autonomous cyan counterpart lives in a divergent reality. Every meaningful event creates two deterministic branches. Choosing SELF improves your outcome; choosing ECHO deliberately accepts a worse local outcome to help your counterpart. The archive must explain cause and effect and allow retracing. Reality drift corrupts the presentation without breaking controls, while symbiotic strain changes the relationship and sound. Three shared anchors create a real, achievable ending.

Use TypeScript, Vite, Phaser 3 and HTML/CSS (the spec explains why). Keep the sim engine independent from the UI. Start with a playable vertical slice immediately: boot -> move -> interact -> branch -> archive -> retrace -> ECHO -> partner response -> win. Build from original pixel art and use the ElevenLabs API offline at build time to pre-render voice, SFX and soundtrack. Never expose the API key in browser code or git. When the key is needed, ask for it privately in the local environment; if unavailable, keep building with placeholders.

You may spawn subagents to handle simulation, UI/visuals and audio/assets, but you own final integration; agree on the TypeScript state contract and file ownership before delegating. Keep changes executable, run tests, and confirm both laptop and mobile controls. Preserve the causal branch history. Do not use live AI for NPC actions or procedural worlds. If there is a conflict between feature breadth and a satisfying completed experience, cut breadth.

You have five hours total. A functioning, finishable game should exist by hour 2.5; the final 45 minutes are strictly for integration, tests and packaging. Deliver a static web build with index.html at its root, a README, gameplay controls, and details of how generated ElevenLabs audio is used. Follow the spec's acceptance tests and report any known limitations instead of saying something works when it has not been tested.

Begin implementing now. Do not ask open-ended design questions; choose sensible defaults and reserve user input for secrets or real blockers. Please show an initial file plan and then execute it immediately.
